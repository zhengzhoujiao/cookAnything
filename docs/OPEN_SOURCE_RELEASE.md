# 公开版本准备与发布

维护者选择保留当前私有仓库，另建无旧历史的公开仓库。本项目的导出脚本不会改写原仓库、推送远端或改变可见性。

## 当前发布条件

- 已从当前 Git 索引移除 `.env`、编译缓存、微信私有开发配置与来源未核实的二进制素材。
- 源码和说明不再包含原管理员密码；后端要求独立配置强凭据。
- 前端不再从环境变量或浏览器设置读取服务方密钥。
- 仍需取得 `liu-ziting/what-to-eat` 对应版本的许可证或修改与再分发授权，详见根目录 `THIRD_PARTY_NOTICES.md`。
- 原私有仓库历史仍包含旧凭据；它必须保持私有，不得把旧分支、标签、bundle 或私有备份推到公开仓库。

## 本地检查与导出

根目录执行：

```sh
python scripts/audit_release.py
python scripts/prepare_release.py --draft
```

`--draft` 仅生成本地审核副本，不能据此认定取得了开源许可。输出位于被忽略的 `.release/public-draft-时间戳/`。脚本从当前工作文件导出，排除本机配置、构建缓存和私有目录；创建新的空 Git 仓库，不复制任何旧提交，不设置远端，也不创建提交。

取得上游许可并按要求添加 `LICENSE`、原许可与署名后：

```sh
python scripts/audit_release.py --require-license
python scripts/prepare_release.py
```

脚本中的 LICENSE 存在检查只用于防止遗漏，不能代替人工核验许可证内容。正式发布前，应使用 Gitleaks 等独立工具再扫描导出目录，并逐项检查 README、LICENSE、第三方声明和截图。仓库自带扫描器只覆盖常见模式及本机已知凭据，不能证明不存在任何敏感信息。

## 在导出副本中验证

确认目录不含 `.env`、`__pycache__`、个人收款码或旧提交。进入导出目录后：

```sh
python scripts/init_local_env.py
docker compose up --build -d
```

检查首页、管理员登录、文本和图片服务配置；有真实服务 Key 时，可自行发起一次生成请求验证兼容性。自动测试不使用付费服务。

如需分发打包后的前端或容器，在根目录按需执行 `python scripts/collect_notices.py`。许可副本生成在被 Git 忽略的 `.release/third-party/`，作为分发附件按许可证要求提供，无需逐个提交到源码仓库。

## 发布与生产配置

许可证确认、验证通过后，在导出目录创建首次提交，再连接新建的公开仓库。只推送新的 main 分支，不使用镜像推送，也不从旧仓库导入历史。

本地配置轮换不会修改已部署服务器的环境变量或数据库。部署者应在正式公开前确认：线上 JWT 密钥独立且未出现在旧配置中、已有管理员密码已修改、必要时轮换模型服务 Key。原私有仓库不应改为 public。
